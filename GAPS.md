What "code" means here: a code node, fixed tts line, counter or flag, router precedence, or an api node covers the sentence.
"prompt" means the rule exists only as text the LLM reads. The check is a set of predicates on the compiled workflow
(`builder/template_cc/rulecov.py`, `CAPS`); a sentence no predicate recognises is `prompt` (its words are in the prompts) or `missing`.
Predicates were calibrated by hand on the p6 builds, so a wrong "code" is possible for rules that look like a known pattern.

## Gap types (prompt-only or missing in 2 or more briefs)

### G1. Nothing the model could say wrongly before verification and with a third party (forbidden-disclosure, 8 briefs)
Examples: "Do not say why you are calling." (brief-a l31, f1 to f6); "Say nothing beyond the opening sentence of rule 1." (brief-a l31);
"Do not say "collections", "debt", "payment" or the product before identity is verified." (brief-a l24, f1 to f4, f6);
f7: "NOT THE CUSTOMER: say nothing about why you call; ask when the customer can be reached."
Today: account facts are withheld by code (`get_account` sits behind `verify_identity`), but the words themselves are the LLM's:
`third_party`, `opening_ask2` and `identity_explain` are free-text nodes. Required: every utterance before verification and every
utterance to a non-customer is a fixed tts line from `policy.lines` (third-party reply = "ask when the customer can be reached"
line; no LLM-phrased turn in those nodes; the LLM only extracts `tp_state` and the offered time). A final word-list check is not
possible in a Vapi workflow, so removing the free text is the enforcement. Owner: **S2** (opening, third party, identity).

### G2. Callback booking is the model's call (conditional-route + deadline-date, 7 briefs)
Examples: "Call `schedule_callback` with the date and the time, then close as `not_reached` / `callback`." (brief-a l32, f1 to f4, f6);
"If that is also outside it, do not schedule." (f1 to f4, f6); f7: "Callback = today or next business day, 10:00-19:00 incl., later than now".
f6 memo amendment: "We no longer book same-day callbacks" (`callback.same_day: false`).
Today: `schedule_callback` is a tool exposed to the `third_party` LLM node; the window is only text (`cb_window_text`), the code never
validates the time it sends. Required: the LLM extracts `cb_date` and `cb_time` as fields; a code node checks the window
(`callback.start/end` inclusive, today only if `same_day`, otherwise the next business day with holidays, later than `now`), counts
the second miss (`callback_reask`), then calls `schedule_callback` from an api node; a bad time never reaches the tool.
Owner: **S2** (third party), because the node and its counters are in the opening/identity half of the graph.

### G3. Fixed sentences the model has to remember (verbatim-line, 8 briefs)
Examples: "Say that the rest stays overdue." (brief-a l72, f1 to f4, f6; f5: "offer the floor once, say the rest stays overdue");
"A question you cannot answer from the tools: say you do not have that information." (brief-a l101, f1 to f4, f6);
"Only "yes", "that's me", "speaking" or the customer's own name counts as confirmation. "Hello", "go ahead" and "who is this" do not."
(brief-a l26, f1 to f4, f6, f7).
Today: "the rest stays overdue" is in the `negotiate` prompt only; an off-script question has no route (the model improvises);
the confirmation vocabulary is the extraction model's reading of the `who1` enum description.
Required: (a) the floor-offer line is built in code and ends with the policy line `lines.rest_overdue` (**S1**, negotiation);
(b) a new extracted intent `asks_unknown` routes to a code node that says `lines.no_information` and resumes the pending step
(**S2**, the same mechanism as `f18_side_resume`); (c) opening extracts the raw text as `who_text` and code matches the brief's
yes-list and no-list (**S2**).

### G4. Amount asks and figures are model-phrased (amount + forbidden-disclosure, 8 briefs)
Examples: "Never ask "how much can you pay?"." and "The agent proposes every amount." (brief-a l70, f1 to f7);
"Do not invent figures, dates or reasons." (brief-a l101, f1 to f4, f6, f7).
Today: only the first ask is a code line (`first_ask_line`); attempt 1 and 2 offers, the "below the floor" reply and the date
proposals are phrased by the `negotiate` LLM from facts, so a "how much can you pay?" or a wrong figure is possible and nothing checks it.
Required: every sentence that carries an amount or a date in `negotiate`, `negotiate_resume` and `promise_confirm` is built in code
from `neg_state` (offer line, floor line, cannot-record line, deadline line) and spoken as tts; the LLM turn is limited to
extraction. Then "never ask how much" holds by construction. Owner: **S1** (negotiation).

### G5. Answer the customer's question first, then resume (ordering, 6 briefs)
Examples: "Answer a question from the customer first (rules 4 and 43)." (brief-a l26, f1 to f4, f6); f5: "answer their question first if they asked one".
Today: AI and scam questions are routed (`g_ai`, `g_scam`, `ai_*`/`scam_*` nodes) and resume works in the identity step; in the opening
step the second ask is not guaranteed to follow the answer. This is exactly S2's `f18_side_resume` (RULES.md rule A on `fix-identity`);
the gap stays open in p6 until that flag is on. Owner: **S2**.

### G6. Policy values the brief states but extraction under-reads (once-rule, 1 brief; shown because it is silent)
f5: "If we get "hello?" or "who's this?", ask once more" yields `ask_limits.right_party: 1`, so the compiler builds no `opening_ask2`
(compare f7 with 2). Required: `policy_check` treats "ask once more" as limit 2 for `right_party`. Owner: **S2**.
It is below the 2-brief threshold but it is a silent wrong value, not a wording gap.

### G7. UNKNOWN rule type: how an answer is formatted for the tool (6 briefs, no library type)
Examples: "Send four digits." (f1 to f4, f6); "Send the postcode in capitals with one space before the last three characters,
for example `LS6 2HQ`." (f2, f5); "Send the eight digits with no spaces." (f4).
These fit none of the 12 types. They are injected verbatim into the `identity` and `identity_explain` prompts by `unknown_rules.py` and
listed in `UNKNOWN.md`. Code behaviour wanted: normalise by `identity.kinds` (`digits`, `postcode`, `date`, `text`) with the per-brief
format (length, case, spacing) in the policy; S2's `f21_spoken_answers` already does digits and spelling alphabets, the postcode
shape and the fixed lengths are the missing part. Owner: **S2**.
